## Findings behind the numbers

**Touch targets (all pages)**
- Buttons are `padding: 6px 12px`, about 32px tall, under the 44px minimum. Header links (`Lighting →`, `← Key remap`) have no padding at all.
- Lighting color swatches are 28px circles, and the color input is 34px tall.

**Remap page**
- The "Swap Alt and Super" label and its explanation run together on one line with no separation (seen in the browser).
- `Apply (0)` is shown while the badge says `Active`: zero mappings but a live Alt/Super swap. The count ignores the swap.
- Locked modifier keys use `opacity: .55` (contrast, verify) and give no visible reason, only a tooltip.
- The picker sits below the fold and its keys are disabled with no explanation until a key is selected.
- Raw Hyprland device names (`telink-rover-84-v3--keyboard`) shown to the user.
- Board labels do not reflect the swap, so "LSuper" and "LAlt" are wrong while it is on.

**Lighting page**
- `<label>` elements are not associated with their controls (`for`/`id` missing); controls only carry `aria-label`.
- No real preview of the keyboard, just a bar whose opacity mimics brightness.
- Speed and brightness show raw numbers (0-4); the app admits it does not know which way speed goes.
- All 18 modes are offered although only Static is verified.

**VIA page**
- Leads with "Mock device", which is meaningless for the keyboard Master owns, and "Connect keyboard", which cannot work for a non-VIA board.
- Empty state is a single hint sentence.

**All pages**
- No shared navigation: three tools are connected by ad-hoc text links in each header, and the current page is not marked (`aria-current` missing).
- Status text floats in the header; errors and success share one tiny line.
- Hover/focus transitions and `prefers-reduced-motion`: no motion exists, so N/A.

## Top fixes
1. One shared app shell with a nav (Remap, Lighting, VIA) and `aria-current`, replacing per-page link rows.
2. 44px minimum targets for buttons, links, swatches and sliders.
3. Remap page: separate "Keyboard settings" (device, Alt/Super swap) from "Key mappings", make Apply reflect all pending changes, and explain locked keys.
4. Lighting page: real keyboard preview, associated labels, plain-language speed and brightness, and clearly mark modes as verified or experimental.
5. Move the VIA page behind a secondary entry and drop "Mock device" from the primary actions.

## Verified in the browser
- Zero interactive elements under 44px tall on all three pages (the check found 8 category tabs at 40px; fixed).
- At 360px wide the page itself does not scroll sideways on any page; only the Remap board scrolls inside its own box.
- Every input and select has an id and a label; the current nav item has `aria-current="page"`; locked keys are at full opacity; no gradients; no emoji.
- Focus returns to the same control after a re-render; the inline confirm moves focus to Cancel, Esc closes it, and focus goes back to the button that opened it (Lighting and VIA).
- Listen captures one key and stops, so Tab is not trapped; an unknown key gives a clear message.
- Remap Apply count: only the swap changed gives "1 change not applied: Alt/Super swap"; a remapped key gets the tinted cap, the pending dot and the right accessible name; Reset this key brings the count back to 0.
- Lighting preview tints every key with the chosen color and brightness; untested modes carry an Untested badge.
